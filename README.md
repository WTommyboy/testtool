# UAT Tool

> Galaxy UAT dispatch & execution platform — create runs online, dispatch to a local agent, drive Codex through the BI UI, and collapse to current-run evidence.

[Status](#status) · [Quick Start](#quick-start) · [Docs Map](#docs-map)

---

## Why

The pain in UAT isn't execution — it's **reproducibility** and **trust**:

- Manual runs miss steps; old screenshots leak into new reports.
- Automated runs (Codex / LLM agents) fabricate evidence, skip the UI, grab the wrong tab, or steal foreground focus.
- Dangerous actions (overwrite, delete, SSO blockers) need human approval — but testcase prose is not authorization.

UAT Tool layers a strict discipline on this pipeline: **one case at a time, current-run evidence only, dangerous actions through Tool Bridge, browser bound by session lease.**

## Key Features

- **Online dispatch + local Agent.** Create runs in the Web UI, dispatch through Railway, execute on a connected Mac Agent.
- **Codex CLI + Playwright MCP execution.** Each case runs in its own auto-generated workspace (see [Per-run workspace](#per-run-workspace)).
- **One-Case-At-A-Time discipline.** Single-case `result.xlsx` → upload → evidence gate → advance. No multi-case accumulation in memory.
- **Tool Bridge.** Native dialogs, irreversible actions, and SSO blockers go through an approval path with full lifecycle status (`pending_approval` / `response_sent` / `response_delivered` / `response_missing`).
- **Evidence gate.** Current-run evidence only, prioritized as DOM > network > chart/table data > UI-triggered downloads > screenshots.
- **Helper library.** High-level actions for BI collage mode: field setup, preview, save, reopen, CSV download, metadata comparison, formula modal.
- **Browser session lease.** Dedicated Chrome profile + tab token binding; helpers don't steal foreground or grab the wrong tab.
- **Result archival.** Server-normalized run state, final aggregate `result.xlsx`, plus concise and full-archive Markdown reports.

## How It Works

```text
Vercel Web UI
  → Railway API / WebSocket Hub
  → Mac Agent
  → Codex CLI + Playwright MCP
  → Galaxy BI UI
  → single-case result.xlsx ingest
  → final aggregate result.xlsx
```

### Per-run workspace

Each run gets a fresh, isolated workspace under `~/.uat-agent/runs/<runId>/`, generated by the Mac Agent on dispatch. The Agent injects:

- **Layer 1 platform skill** (`agent-skills/uat-tool/`) — general UAT execution discipline.
- **Domain pack** (e.g. `domain-packs/BI/`, `domain-packs/BI_OFFICIAL_UI_COLLAGE/`) — domain-specific rules, metadata reference, helper hints.
- **Test package** — testcase xlsx + assignment / execution markdown.
- **Browser session lease** — Chrome tab pinned by token in `input/browser-session.json`.

Codex CLI launches inside this workspace and only sees what was injected. Nothing carries across runs or cases.

## Quick Start

Minimal local setup:

```bash
git clone <repo>
cd <repo-dir>
npm install
npx playwright install chromium
npm run dev          # API at http://localhost:3000
```

Start the local Mac Agent:

```bash
npm run build --prefix agent
node agent/dist/cli.js start
```

Verify a deployed environment:

```bash
curl -fsS https://<your-api-host>/version
curl -fsS https://<your-api-host>/health
```

## Usage

A typical run:

1. Open the Web UI at `https://<your-web-ui-host>/` and create a run.
2. Upload the test package: `testcase.xlsx` + Codex assignment markdown + execution-instruction markdown. Authoring rules live in `docs/authoring/UAT_三文件撰寫規則.md`.
3. Start the run. Railway dispatches to the connected local Mac Agent.
4. The Agent launches Codex per case in manifest order; Codex drives the Galaxy BI UI through Playwright MCP.
5. Each case ends with an automatic single-case `result.xlsx` upload, gated by the evidence gate before advancing.
6. When all cases finish, download the aggregate `result.xlsx`, the concise Markdown report, and the full-archive Markdown report.

Human approval points (native dialogs, overwrite, delete, SSO blockers) surface in the Tool Bridge panel in the Web UI. Testcase prose is not authorization.

## Development

```bash
npm run typecheck                # root
npm run build                    # root
npm run typecheck --prefix agent
npm run build --prefix agent
npm run build --prefix web
npm run create:domain-pack -- --name MY_DOMAIN --display "My Domain"
npm run verify:domain-pack -- --name MY_DOMAIN
```

The repo also ships a `verify:*` suite (capability-gate, package-consistency, helper-hints, result-evidence-gate, tool-bridge, case-advance-policy, agent-resume, ...). Run `npm run` to list all available scripts.

## Deployment

- Railway deploys from branch `codex/uat-tool-mvp`.
- Playwright Linux dependencies are handled by `nixpacks.toml`. Do not set `PLAYWRIGHT_BROWSERS_PATH=0` on Railway.
- If a deploy reports missing browser executables, clear the build cache and redeploy.
- Dev sandbox: API at `https://<your-dev-api-host>`, launchd label `com.<org>.uat-agent-dev`, working dir `$HOME/.uat-agent-dev`.

Replace `<your-*-host>` placeholders with your own deployment URLs.
