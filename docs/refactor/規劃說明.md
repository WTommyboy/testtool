## 2. 目前目標

UAT Tool 要從「BI 專用測試輔助工具」演進成「Galaxy 通用 UAT 派工平台」。

最終使用方式是:

1. PM 進入線上工具 `https://testtool-eight.vercel.app/`。
2. PM 建立一輪測試 run,上傳 testcase xlsx、startup instruction、多份支援 md/csv。
3. PM 選擇執行方式:目前是 `Agent 互動執行`,未來可擴展到遠端機器或雲端執行器。
4. Railway 後端派工給已連線的 Mac Agent。
5. Mac Agent 在 Tommy 本機啟動 Codex CLI + Playwright MCP,用本機 Chrome / Galaxy SSO session 跑測試。
6. Codex 依 Layer 1 平台規則與 Domain rules 執行測試,必要時透過 Tool Bridge 暫停等 Tommy 處理。
7. Agent 上傳 result.xlsx、agent.log、partial artifacts。
8. Railway 解析結果入庫,Web UI 顯示 case 結果、log、phase、bug。

## 3. 現行部署架構

### 3.1 Vercel

Vercel 目前負責前端 UI:

- 網址: `https://testtool-eight.vercel.app/`
- 主要功能:
  - 測試執行頁
  - 執行記錄頁
  - Agent 狀態顯示
  - Run logs / events / phase timeline
  - Tool Bridge 人工處理區
  - case 結果與 bug 顯示
- Vercel 不保存秘密金鑰。
- Vercel 不直接跑 Playwright。
- Vercel 透過 `VITE_API_BASE_URL` 呼叫 Railway API。

### 3.2 Railway

Railway 目前負責後端與中樞:

- API: `https://testtool-production.up.railway.app`
- 主要功能:
  - 建立 run
  - 儲存上傳檔案
  - 解析 testcase xlsx
  - 管理 Agent token
  - WebSocket `/agent-ws`
  - 派發 `task.dispatch`
  - 接收 Agent progress / phase / stdout / stderr / result
  - 解析 result.xlsx
  - 提供 run summary / logs / cases / agents API
- Railway 是權限、資料、檔案與派工的 source of truth。

### 3.3 Mac Agent

Mac Agent 是本機執行器:

- package: `uat-tool-agent`
- binary: `uat-agent`
- 本機常駐: `launchd` service `com.tommy.uat-agent`
- 本機設定: `~/.uat-agent/config.json`
- 本機工作目錄: `~/.uat-agent/runs/<runId>/`
- Chrome profile: `~/.uat-agent/chrome-profile`
- 主要責任:
  - 連 Railway WebSocket
  - 回報 doctor 狀態
  - 接收 `task.dispatch`
  - 下載 input files
  - 產生 run brief、case manifest、rule index、BI helper guidance
  - 啟動 persistent Chrome CDP
  - 啟動 Codex CLI
  - 串流 Codex progress / phase
  - 解析 Tool Bridge request
  - 上傳 result.xlsx / agent.log / partial artifacts

### 3.4 Codex CLI + Playwright MCP

Codex CLI 是實際測試代理:

- Codex 透過 Playwright MCP 操作 Galaxy BI UI。
- Playwright MCP 接到本機 persistent Chrome CDP。
- Chrome profile 維持公司 SSO session。
- Codex 不應直接打 BI API 取代 UI。
- Codex 不應用內部 JS 函式設定測試狀態。
- Codex 必須依 evidence gate 判斷 PASS / FAIL / BLOCKED。

## 4. 最新執行流程

### 4.1 建立 Run

PM 在 Web UI:

1. 選 Domain,目前預設 `BI`。
2. 上傳 testcase xlsx。
3. 上傳多份 testcase 文件,第一份作為 startup instruction,其餘作為 supporting docs。
4. 可選 baseline/reference csv。
5. 選 Agent 互動執行。
6. 按開始執行。

Railway:

1. 建立 run。
2. 解析 xlsx 初始 case 列表。
3. 儲存上傳檔。
4. 產生 Agent 可下載的 signed/input URLs。
5. 透過 WebSocket 派發 `task.dispatch`。

### 4.2 Agent 準備階段

Mac Agent 收到 task 後:

1. 建立 `~/.uat-agent/runs/<runId>/`。
2. 下載 xlsx、md、startup instruction、domain pack、supporting docs。
3. 複製 Layer 1 Skill 到 run workspace。
4. 複製 BI domain 參考文件。
5. 產生:
   - `input/run-brief.md`
   - `input/case-manifest.json`
   - `input/current-case.json`
   - `input/cases/*.json`
   - `input/rule-index.json`
   - `input/bi-ui-helper-guidance.md`
   - `input/preflight-auth-check.md`
   - `input/run-state.json`
   - `input/generated-guides.json`
6. 開啟或重用 persistent Chrome CDP。
7. 啟動 Codex CLI。

### 4.3 Codex 執行階段

Codex 的最新啟動策略是 progressive disclosure:

1. 先讀 `input/run-brief.md`。
2. 先讀 `input/preflight-auth-check.md`,並做最小 auth/reachability check。
3. preflight 通過後才讀 `input/current-case.json` 與 `input/run-state.json`。
4. 用 `input/rule-index.json` 決定必要規則。
5. BI UI 操作前讀 `input/bi-ui-helper-guidance.md`。
6. 必要時才讀完整 Layer 1 或 BI domain rules。
7. 一次只跑一個 case。
8. 一個 case 跑完後要先寫 evidence/result,再進下一個 case。

Preflight 只允許確認 DEV URL、SSO/login、載入失敗、401/403、空白頁與 browser 可用性。不可在 preflight 階段取 baseline、調整欄位/日期/篩選、儲存報表或執行任何 testcase step。

### 4.4 Tool Bridge 階段

當 Codex 遇到以下情境,必須停止並輸出 Tool Bridge request:

- Galaxy SSO / login required
- native alert / confirm
- 儲存、刪除、覆蓋等不可逆操作
- 規格或判定灰色地帶
- Playwright recovery / browser closed / session blocked

Agent 解析 `[TOOL_REQUEST]{...}[/TOOL_REQUEST]` 後:

1. 若 request 是非 SSO/login/auth 的 actionable request，Mac Agent 依 auto approval policy 直接產生 `tool_response`，server 寫 approved audit row，Agent 維持 busy/currentRunId 並續跑同一個 Codex thread。
2. 若 request 是 SSO/login/auth blocker，Web UI 顯示「等待人工處理」。
3. Tommy 處理 SSO/login 後按「已處理 / 繼續執行」。
4. Railway 送 `tool_response` 給 Agent。
5. Agent 用 `codex exec resume --json <thread_id>` 續跑同一個 Codex thread。

### 4.5 結果回傳階段

Codex 正常完成時:

1. Codex 應產出 `output/result.xlsx`。
2. Agent 上傳 `output/result.xlsx`。
3. Agent 上傳 `output/agent.log`。
4. Railway 解析 result.xlsx。
5. case results / bugs 入庫。
6. Run 進入 terminal status。

若 Codex 被取消或失敗:

1. Agent 仍會保存 partial logs。
2. Agent 會產生 fallback result.xlsx。
3. fallback result 不會被當成真實 UAT PASS。
4. Web UI 可看 partial artifacts 與失敗原因。

### 5.1 Layer 1 平台層

位置: `agent-skills/uat-tool/`

Layer 1 是 Galaxy 通用 UAT 平台規則,不得混入 BI 專用測試邏輯。

目前包含:

- `SKILL.md`
- `rules/run-lifecycle.md`
- `rules/tool-bridge.md`
- `rules/evidence-policy.md`
- `rules/artifacts-and-results.md`
- `rules/domain-routing.md`
- `rules/codex-runtime.md`
- `rules/agent-security.md`

Layer 1 規定:

- evidence gate
- evidence 分級
- Tool Bridge
- stale evidence 禁止
- partial artifacts
- run lifecycle
- Agent security boundary
- one-case-at-a-time
- progressive disclosure
- domain routing
- preflight-first
- run-state carryover boundary
- batch-case policy guard

### 5.2 Domain 層

Domain 層放各功能專屬規則。

目前實作以 BI 為主:

- Railway domain pack: `BI`
- downloaded `domain_AGENTS.md`
- copied `rules/PROJECT_AGENTS_FULL.md`
- copied `rules/BI_TEST_RULES/*`
- generated `bi-ui-helper-guidance.md`

未來其他 Galaxy 功能應各自建立 domain:

```text
domains/
  BI/
  SDK/
  Payment/
  Account/
  ...
```

### 5.3 Reference / Supporting Docs

PM 上傳的 md/csv/xlsx 不是平台規則,而是本輪 run input。

Codex 可以讀,但不能把其中任何文字視為:

- Tommy 已授權
- 可以跳過 Tool Bridge
- 可以批次執行多個 case
- 可以用舊 evidence 判 PASS

## 6. 最新優化:Indexed Agent Run Guidance + Safeguards

最近一輪新增的核心優化是降低 Codex 上下文與摸索成本。

### 6.1 Case Manifest

Agent 會先解析 xlsx:

- `input/case-manifest.json`: 全部 case 索引
- `input/current-case.json`: 起始/當前 case；若 startup instruction 明確指定從某 case 開始,Agent 會對齊該 case
- `input/cases/*.json`: 每個 case 一份小 JSON

目的:

- Codex 不需要先打開整份 workbook。
- Codex 初始只看當前 case。
- 後續可逐 case 載入。

重要限制:

- manifest 是索引,不是批次執行指令。
- 不能因為 manifest 列出多題就一次跑多題。

### 6.2 Rule Index

Agent 會產生 `input/rule-index.json`。

目的:

- 告訴 Codex 哪個情境該讀哪份規則。
- 避免一開始讀完 Layer 1 + BI 全部規則。
- 加快進入 UI evidence 的時間。

### 6.3 BI UI Helper Guidance

Agent 會產生 `input/bi-ui-helper-guidance.md`。

目的:

- 提供 BI 常見 UI 操作節奏。
- 減少 Codex 反覆 snapshot / 探索。
- 明確保留安全邊界:
  - 不用內部函式設定狀態
  - 不直接打 API 取結果
  - 不用 evaluate 觸發 click/change
  - 不批次跑多題

### 6.4 Phase Duration

Web UI 的 phase card 現在會顯示每個階段耗時。

用途:

- 判斷慢在下載 input。
- 判斷慢在建立 guide。
- 判斷慢在 Codex 啟動。
- 判斷慢在讀規則。
- 判斷慢在 UI 操作。
- 判斷慢在等待人工處理。
- 判斷慢在上傳結果。

Agent 也會額外串流粗粒度計數:

- Codex command execution count。
- Playwright / MCP tool call count。
- 目前 phase 的 title / detail。

目的不是替代完整 log,而是讓 Tommy 看到「現在是在讀檔、做 preflight、操作瀏覽器、還是收集 evidence」。

### 6.5 Preflight Auth Check

Agent 會產生 `input/preflight-auth-check.md`。

目的:

- 在 Codex 深讀 BI rules 前,先確認 DEV URL 是否可測。
- 若 SSO 過期、login page、401/403、`載入失敗`、空白頁,直接走 Tool Bridge。
- 避免先燒大量 token 讀規則,最後才發現無法進頁面。

限制:

- preflight 不得執行 testcase step。
- preflight 不得取 baseline。
- preflight 不得設定欄位、篩選、分組、日期。
- preflight 不得新增、儲存、刪除報表或專案。

### 6.6 Run State / Carryover Boundary

Agent 會產生 `input/run-state.json`。

目的:

- 明確列出本 run 允許 carryover 的資料,例如同 run 建立的臨時報表、同 run baseline、Tool Bridge approval。
- 明確標示 previous-case evidence、prior workbook rows、previous UI state 不能直接拿來證明 current case。
- 支援未來逐 case reset,避免 Codex 靠記憶跨題混用 evidence。

目前規則:

- `case-manifest.json` 只是索引。
- `run-state.json` 才是 carryover contract。
- previous-case evidence 可作 traceability,不可作 current case result 的 proof。

### 6.7 Evidence 分級

最新 Layer 1 與 BI helper 已改成 evidence tiering:

1. DOM / form state。
2. Network observation。
3. Chart / table / downloaded data。
4. Screenshot。

截圖不再要求每一步都做,但以下情境仍需保留:

- Tool Bridge request 前後。
- FAIL / bug evidence。
- 建立、儲存、刪除、重新載入等重大狀態轉換。
- final evidence 需要人眼快速確認時。

原則:用結構化 evidence 降低 token 與人工判讀成本,但 bug 與不可逆流程仍需可視佐證。

### 6.8 Current Case Pack / Reference Index

Agent 現在會在每個 run workspace 產生:

- `input/current-case-pack.md`
- `input/current-case-pack.json`
- `input/reference-index.json`
- `input/supporting-docs-manifest.json`

目的:

- 讓 Codex 先讀「目前 case 的執行卡」,不要先讀整本 xlsx 或全部 supporting docs。
- 讓 Codex 用 exact path 找資料,避免在 workspace 做廣泛搜尋。
- 明確標示 current-case-pack 是 plan card,不是 result evidence。
- 每題只暴露當前 case 的 evidence requirement,降低跨題混用風險。

### 6.9 Document Consistency Gate

Agent 現在會產生 `input/document-consistency.json`。

用途:

- 檢查 startup instruction 指定的起始 case 是否與 workbook 狀態一致。
- 若 startup instruction 說從後面的 case 開始,但前面 case 在 workbook 內沒有結果或 detail_json,視為文件衝突。
- 文件衝突時,Codex 不應開瀏覽器,而是先發 Tool Bridge `ambiguity_decision`。

這是為了避免「指派文字寫 DEMO-B-01,但 xlsx 實際應從 DEMO-A-01 開始」這類錯誤直接進入測試。

### 6.10 Evidence Templates / Result Template / Network Guidance

Agent 現在會產生:

- `input/evidence-templates/index.json`
- `input/result-template.xlsx`
- `input/network-observation-guidance.md`

用途:

- Evidence templates:讓 Codex 依 current case 類型選最小 evidence 結構,不用每次重新發明 detail_json。
- Result template:提供 `output/result.xlsx` 欄位形狀參考,但 Codex 仍負責寫正式結果。
- Network guidance:明確 network 只能作為 UI 觸發後的觀察,不可直接打 BI API 取代 UI。

## 7. 嚴格規則是否過度

目前判斷:

不應放鬆的規則:

- 一次只跑一個 case
- 每 case 必須有 current-run evidence
- 舊 workbook / 既有報表不可當作本 run evidence
- SSO/login/auth 必須人工 Tool Bridge；alert / confirm / 不可逆操作可由 Mac Agent auto approval policy 回覆，但仍必須留下 Tool Bridge request/response evidence
- 不可直接打 BI API 取代 UI
- 不可用內部 JS 函式設定測試狀態
- partial / failed run 仍要保存 log/artifacts

可以優化的不是「規則嚴格度」,而是「讀取與執行路徑」:

- 用 run brief 取代大 prompt。
- 用 case manifest 取代整本 xlsx。
- 用 current-case-pack 取代先讀整本 testcase/supporting docs。
- 用 reference-index 取代廣泛搜尋。
- 用 rule index 取代一次讀全部 rules。
- 用 evidence templates 取代每次重新設計 detail_json。
- 用 helper guidance 減少 UI 摸索。
- 用 phase duration 找瓶頸。

換句話說:正確性閘門維持嚴格,上下文載入要變輕。

## 8. 防止重新發生「多題混跑」

這是目前最重要的風險之一。

為避免為了加速又回到過去的錯誤,目前在多層加入防線:

1. Layer 1 Skill 要求 one-case-at-a-time。
2. Agent generated `AGENTS.md` 要求 one-case-at-a-time。
3. `run-brief.md` 明確說 case manifest 只是索引。
4. Codex prompt 明確禁止 batch multiple case flows。
5. `rule-index.json` 標註 manifest 不可作為批次執行授權。
6. `bi-ui-helper-guidance.md` 明確說 helper 不可包含多 case 流程。
7. `current-case-pack.*` 明確寫「plan card 不是 result」。
8. `document-consistency.json` 先阻擋指派文字與 workbook 的起始 case 衝突。
9. result fallback 不再把 Codex 成功退出誤判為 UAT PASS。
10. Agent 會掃描 Playwright MCP session log,若同一 tool call 疑似同時處理多個 case,標 `BATCH_CASE_POLICY_VIOLATION`。
11. `run-state.json` 明確把 previous-case evidence 標為 isolated,不可證明 current case。

後續仍建議補強:

- result parser 檢查每個 case 的 detail_json 是否有獨立 evidence timestamp。
- Web UI 顯示每 case 的 execution evidence count。

## 10. 目前限制

### 10.1 Codex 仍可能偏慢

原因:

- Codex CLI 啟動與 reasoning 本身有固定成本。
- Playwright MCP 每個 snapshot / click / DOM read 都有往返成本。
- BI UI 本身某些操作需等待 DOM 重畫。
- 若 Codex 過度保守,仍可能多讀文件或多做驗證。

改善方向:

- 繼續縮小 prompt。
- 用 per-case JSON 作為主要輸入。
- 用 preflight-first 避免 SSO 失效時先燒規則 token。
- 用 run-state.json 控制 carryover,不要靠 Codex 記憶。
- 把 BI helper guidance 再濃縮成更可執行的 recipe。
- 未來可做「安全 Playwright helper」,但必須確保不繞 UI、不批次多 case。

### 10.2 Tool Bridge 仍是文字協議

目前 Tool Bridge 透過 Codex assistant output 的 `[TOOL_REQUEST]...[/TOOL_REQUEST]` 解析。

風險:

- Codex 可能漏欄位。
- Codex 可能輸出非標準 JSON。
- Codex 可能在 request 後又產出一般文字。

目前已做:

- parser fixture
- schema validation
- alias normalization
- invalid request 會 fail,不再默默通過

後續可做:

- 更結構化的 Codex tool call / MCP bridge。
- Web UI 顯示 request schema error 與修正建議。

### 10.3 真實 BI 測試仍需打磨

目前真實 DEMO smoke 已能:

- 啟動 Chrome / Playwright
- 進 Galaxy BI
- 操作 UI
- 發 Tool Bridge request
- 串流 log / phase

但仍需優化:

- Codex 太慢時的階段分析。
- result.xlsx 必須保證真實 case 結果,不可只寫 Agent summary。
- Tool Bridge request 欄位要穩定。
- case manifest 應逐 case 更新 current pointer。
- BI domain rules 應從 legacy AGENTS 慢慢拆成 domain pack。

## 13. 核心判斷

目前方向是正確的:

- 把執行能力放在本機 Mac,解決公司 SSO / Chrome profile / Playwright 環境問題。
- 把資料、狀態、歷史、派工放在線上工具,保留 PM 的單一入口。
- 用 Layer 1 + Domain Pack 分層,避免 BI 規則綁死平台。
- 用 Tool Bridge 處理人工授權與 SSO recovery。
- 用 indexed guidance 降低 Codex token 與時間成本。
- 用 preflight-first 避免 SSO/載入問題造成前置 token 浪費。
- 用 run-state.json 讓跨題 carryover 顯性化,避免 evidence 混用。
- 用 batch-case detector 防止加速時重新出現多題混跑。

但短期不能為了速度犧牲:

- evidence gate
- one-case-at-a-time
- Tool Bridge
- stale evidence 防線
- partial artifact 保存

速度問題應透過「更好的索引、摘要、階段觀測、helper guidance」處理,不是透過「少驗證、混跑多題、跳過 UI」處理。
